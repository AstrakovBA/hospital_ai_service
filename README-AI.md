# README-AI.md — Правила для AI-ассистента

## Проект
Медицинская информационная система. Сервис генерации черновика ответа пациенту.
Стек: Java 21, Spring Boot 3.3, GigaChat API.

## Архитектура
Слоистая: Controller ? Service ? AiGateway ? LlmClient ? Provider.
Бизнес-логика изолирована от конкретного LLM-провайдера.

## Структура пакетов
- `controller` — REST-эндпоинты, валидация входных данных
- `service` — бизнес-логика, формирование prompt, санитизация
- `client` — HTTP-клиенты для внешних сервисов
- `llm` — абстракция LlmClient, AiGateway, реализации провайдеров
- `dto` — объекты передачи данных (вход/выход)
- `domain` — доменные перечисления и модели
- `config` — конфигурация, свойства
- `exception` — кастомные исключения и обработчики

## РАЗРЕШЕНО
1. Создавать новые DTO в пакете `dto` (record-классы с валидацией).
2. Добавлять бизнес-логику ТОЛЬКО в `service`-слой.
3. Вызывать внешние API ТОЛЬКО через `client`-слой или `llm`-слой.
4. Писать unit-тесты для `service`-слоя с моками (`@MockBean`, Mockito).
5. Добавлять новые категории вопросов в `QuestionCategory`.
6. Обновлять OpenAPI-спецификацию при изменении контракта.
7. Добавлять логирование (без персональных данных пациентов).
8. Создавать новые реализации `LlmClient` при подключении провайдера.

## ЗАПРЕЩЕНО
1. Хранить секреты (API-ключи, пароли, токены) в `application.yml` или коде.
2. Вызывать LLM или внешние сервисы из `Controller`.
3. Менять публичный API без обновления документации и OpenAPI.
4. Смешивать доменные модели и DTO (не передавать entity наружу).
5. Удалять тесты ради успешной сборки.
6. Логировать персональные данные пациентов (ФИО, диагнозы, вопросы).
7. Генерировать медицинские назначения, диагнозы, рекомендации по лечению.
8. Использовать `RestTemplate`/`WebClient` напрямую в `Service`.
9. Хардкодить URL, ключи, параметры моделей в коде.
10. Обходить `AiGateway` при обращении к LLM.

## Медицинские ограничения (критично!)
- Сервис НЕ является медицинским устройством.
- Ответы НЕ должны содержать: диагнозы, назначения, дозировки, интерпретацию анализов.
- Любой медицинский вопрос ? перенаправление к врачу.
- Каждый ответ содержит disclaimer об информационном характере.

## Тестирование
- Unit-тесты: `service`, `llm` (с моками).
- Интеграционные: `@SpringBootTest` с моками LLM.
- Запуск: `./mvnw test`

## Конфигурация
- Секреты: только через переменные окружения.
- Провайдер: `llm.active-provider` в `application.yml`.
- Fallback: `llm.fallback-provider`.
